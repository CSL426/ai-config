# 工作線交接

使用者的流程是:交接 → `/clear` → 接手,同一個 session 接續同一條線。
交接取代壓縮:只帶整理過的進度,不帶整段對話裡對的錯的混在一起的歷史。

## 交接(收工、context 快滿、要 clear 之前)

1. 先判斷還有沒有事要做。**Next 寫不出任何一項,就不要寫交接**:接手時那則交接
   已經結案了,告訴使用者這條線做完了即可。

2. 還有事,就寫交接。名稱用這條線在做的事,簡短好認;內容寫給不知道前因後果的人,
   用這幾個標題,沒東西的段落省略:

   ```
   ## Goal       這條線要達成什麼
   ## State      現在到哪裡:分支、版本、部署狀態
   ## Verified   實際驗證過的結論,附上怎麼驗的
   ## Refuted    試過但不成立的
   ## Unknowns   還不確定的,別寫成結論
   ## Next       還沒做的,一項一行
   ```

   ```
   acg memory handoff write "工作線名稱" "內容"
   ```

   **Verified 跟 Unknowns 一定要分開**:沒驗過的推測寫成事實,下一個人會照著做。

3. 寫完告訴使用者可以 `/clear`,之後說「接著做」就能接回來。

## 接手(clear 之後、開新 session)

1. 先不帶名稱認領,它會找這個 session 名稱留下的線:

   ```
   acg memory handoff claim
   ```

2. 成功就讀它印出的進度,用自己的話跟使用者確認接手點,再開始做。
3. 失敗(讀不到名稱、沒有、或不只一條)才列出來:`acg memory handoff list`。
   只有一條就直接認領;兩條以上問使用者要接哪條,不要自己挑。
4. 標著 `⚠ 可能已過期` 的線,裡面的進度可能已經被別處的工作蓋過去:先對照現況,
   不要照著它的待辦直接做。
5. 接手會把那則交接結案並記下是誰接的。被拒表示已經被別的 session 接走;
   把是誰告訴使用者,不要重試。

## 不用管的事

- 結案的線滿一個月、或任何一條線一個月沒人動,`list` 會自動移到 `handoff/archive/`。
- 這跟 session 開頭 remember 印的 `=== HANDOFF ===`(日誌位置)是兩回事。
