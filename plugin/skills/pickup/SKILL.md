# pickup:接手一條交接出來的工作線

引數的第一個詞若是一個存在的目錄,就是要看那個專案的交接線,列表時把它傳給 `list`;
其餘的詞才是工作線名稱。沒給路徑就看目前這個專案。

沒指定名稱時,先試著認領這個 session 自己留下的線:

```
acg memory handoff claim
```

不帶名稱時,它找的是交接時記下的 session 名稱跟現在一樣的線。使用者的流程是
handoff → `/clear` → pickup,名字不會變,所以這一步通常就接到了,不用再問。

它說讀不到名稱、沒有這個名稱留下的線,或不只一條時,才列出有哪些可接(有路徑就接在後面):

```
acg memory handoff list [專案路徑]
```

列表只含這個專案的工作線,照數量決定:

- **沒有**:告訴使用者目前沒有可接的線,到這裡結束。
- **只有一條**:直接認領,不用再問,因為沒有第二個選項。認領前先把名稱與摘要說一遍,
  讓使用者知道接的是哪條。
- **兩條以上**:問使用者要接哪一條,不要自己挑。

指定了名稱,或只有一條可接,就認領它(名稱含空格要用引號):

```
acg memory handoff claim "<工作線名稱>"
```

這行是格式示範,要換成實際的名稱。

標著 `⚠ 可能已過期` 的線,裡面的進度可能已經被別處的工作蓋過去:先對照現況,不要照著它的
待辦直接做。

認領會印出那條線的進度,同時把這則交接結案、記下是誰接走的。讀完之後,用你自己的話跟使用者
確認理解的接手點,再開始工作。收工時若還沒做完,用 `/acg handoff` 寫一份新的交接。

被拒絕表示這條線已經被別的 session 接走了。把是誰告訴使用者,不要自己重試。

引數:`$ARGUMENTS`
