---
description: 接手一條交接出來的工作線,並讀取它的進度
argument-hint: '[專案路徑] [工作線名稱]'
allowed-tools: Bash(acg memory handoff:*), Bash(ai-config memory handoff:*)
---

使用者要接手一條先前交接出來的工作線。

引數:`$ARGUMENTS`

引數的第一個詞若是一個存在的目錄,就是要看**那個專案**的交接線,列表時把它
傳給 `list`;其餘的詞才是工作線名稱。沒給路徑就看目前這個專案。

若使用者沒指定名稱,先試著認領**這個 session 自己留下的線**:

```
acg memory handoff claim
```

不帶名稱時,它找的是交接時記下的 session 名稱跟現在這個 session 一樣的線。使用者的
流程是 handoff → `/clear` → pickup,名字不會變,所以這一步通常就接到了,不用再問。
成功就直接跳到下面「認領會印出那條線的進度」。

如果它說讀不到名稱、沒有這個名稱留下的線,或不只一條,才改成列出有哪些可接(有路徑就接在後面):

```
acg memory handoff list
acg memory handoff list /path/to/other/project
```

列表已經只含這個專案的工作線,照數量決定:

- **沒有**:告訴使用者目前沒有可接的線,到這裡結束。
- **只有一條**:直接認領它,不用再問 —— 沒有第二個選項時,問是多餘的。
  認領前先把那條線的名稱與摘要說一遍,讓使用者知道接的是哪條。
- **兩條以上**:問他要接哪一條,不要自己挑。

指定了名稱,或只有一條可接,就用 Bash 認領它(名稱含空格要用引號):

```
acg memory handoff claim "使用者說的那條線"
```

**不要照抄字面值**,要換成實際的名稱。

認領會印出那條線的進度。讀完之後,用你自己的話跟使用者確認你理解的接手點,再開始工作。

如果認領被拒絕,表示**另一個 session 正在做這條線**(超過一天沒動的會自動接手,
不會被拒)。把持有者告訴使用者,讓他決定要不要強制接手,不要自己重試。

認領時若印出「原本由 … 持有,超過 N 小時沒有動靜,已接手」,表示接走的是一條
沒收好的線。那份進度可能停在半路,不是寫完才交出來的 —— 讀的時候要當成半成品,
跟現況對照過再動手。
